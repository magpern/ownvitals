# Languages: response codes and health wording

Written by #250 (G4, ADR 0015 sections 5 and 6). The runtime and the catalogue rules are in
[frontend.md](frontend.md) ("Languages"); this file is the code list and the owner's review list.

## Response codes (section 6)

A user-facing response carries a stable code, never an English sentence. Parameters are numbers,
ISO dates or allowlisted enums, never free text or another user's values. Log lines, admin-only
output and the CLI stay English.

- The list is `backend/src/ownvitals/response_codes.py`, one set per route family (`auth`, `jobs`,
  `job_failures`, `connections`, `views`).
- `backend/tests/test_response_codes.py` checks that the jobs and connections routes emit only
  listed codes, that `assert_response_code(family, body)` fails on an unknown one, and that
  `frontend/src/api/codes.json` equals the list.
- The frontend words a code with `codeMessage` (`src/api/codes.ts`): `errors.reason.<code>` first,
  then `codes.code.<code>`; an unknown code shows `errors.generic`. `src/api/codes.test.ts` fails
  when a listed code has no English entry.

Adding a code: add it to its family, regenerate the list, add the English text to
`src/i18n/en/codes.ts` (and the English copy to `sv/codes.ts`, listed in `untranslated.ts`):

```bash
cd backend && uv run python -c "import json; from ownvitals.response_codes import all_codes; \
print(json.dumps(all_codes(), indent=2))" > ../frontend/src/api/codes.json
```

Replaced sentences: `error_message` of a job (now `error_category` alone), `removal` of a
disconnect and an account deletion (now `revoke_incomplete`), `method.text` of a metric detail (now
`method.code` `daily_summary`, worded from `method.parameters`).

## Health wording (section 5)

**Health wording** is the owner's medical-claims review at M8 (PLAN-operations section 9.3), in
both languages. Every key of `src/i18n/*/health.ts` is health wording; a translation may not
change a tier, a threshold or a confidence, or add advice the English text does not give. Nothing
translated is stored: findings hold `rule_id`, `tier` and `evidence`, and the page words them
(ADR 0010 section 8). `frontend/src/api/rules.json` lists every rule id of the specs and
`codes.test.ts` fails when one has no name and text.

Tiers and severities:

- `health.tier.device`, `health.tier.trend`, `health.tier.experimental`, `health.tier.system`,
  `health.tier.experimental.note`
- `health.severity.urgent`, `health.severity.attention`, `health.severity.info`
